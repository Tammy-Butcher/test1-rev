There are several different stages/activities while hosting a production webcast.  These include:

1. Viewing Event Hosting Details
2. Starting and Broadcasting the Webcast
3. Activities During the Webcast
4. Recording the Webcast
5. Viewing and Removing Attendees
6. Controlling the Webcast

These are discussed below.

## Viewing Event Hosting Details

If an **Event Admin** or **Event Host** (that is assigned) clicks on an event from [The Event Calendar](doc:the-event-calendar), the [Webcast Settings Dashboard](doc:webcast-settings-dashboard) displays with details related to hosting it; including the ability to either edit or start the webcast's **Pre-Production** or **Main Event** (if it is time to start the event).

<Image title="eventAdminView.png" alt={1202} align="center" src="https://files.readme.io/5549e18-eventAdminView.png">
  The Event Admin/Host view displays details that may be edited along with the ability to start the webcast
</Image>

In addition to the **Webcast Links** and ability to **Start** the event, the **Webcast Settings Dashboard** manages:

* [Event Invitations](doc:webcast-settings-dashboard#event-invitations) for multiple recipients and specific individuals (if early registrations are used for **Public** events)
* [Registration Management](doc:webcast-settings-dashboard#review-early-registrations-for-public-events) for Public events
* [Embed](doc:webcast-settings-dashboard#embed-an-event) options for the event (if enabled)
* [Duplication](doc:webcast-settings-dashboard#duplicate-a-webcast) options for the event
* [Webcast Reports](doc:webcast-settings-dashboard#webcast-reports)

## Starting and Broadcasting the Webcast

Click the **Start Webcast** button from event settings to start your Main Event. You may also click on the **Event Name** in the **Upcoming Events** carousal from the [Rev Home Page](doc:the-rev-home-page). Note:  You must have configured and saved your event first.

> 🚧 Important!
>
> This button is *not* available until start date and time of the event and until the dry run of the event has ended if you have set up **Pre-Production** time.
>
> View: [Prepare a Dry Run](doc:prepare-a-dry-run)

<Image title="startWebcastButton.png" alt={1202} align="center" src="https://files.readme.io/7db2019-startWebcastButton.png">
  The Start Webcast button is available after pre-production duration is concluded and at the start time of the Main Event
</Image>

This displays **Event Admin/Event Host** view. If an Event Moderator is set up to control presentation slides, they can also be tested at this point before broadcasting begins.

<Image title="eventAdminHostView.png" alt={1197} align="center" src="https://files.readme.io/1c0ddce-eventAdminHostView.png">
  Event Admin / Event Host view is displayed when the Main Event is started (before broadcasting)
</Image>

When in Event Admin/Event Host view:

<Image title="topYellowBar.png" alt={981} align="center" src="https://files.readme.io/9164262-topYellowBar.png">
  While you are not broadcasting, the top bar is yellow.  If you begin broadcasting to attendees, this bar turns blue.
</Image>

The **yellow** bar across the top of the webcast screen indicates that you are *not* broadcasting. This changes to a **blue** bar if you click the **Broadcast** button to begin broadcasting the event to attendees.

<Image title="topBlueBar.png" alt={658} align="center" src="https://files.readme.io/7f06c68-topBlueBar.png">
  When you begin broadcasting, attendees can view your Webcast and the blue bar across the top of your screen indicates this
</Image>

> 👍 Tip
>
> It is recommended to wait a few minutes after starting a webcast *before* broadcasting. This ensures that configured resources, which may vary across configurations, are ready for distribution to all endpoints.

The **Video**, **Audio**, **Presentation**, and **Slides** tabs are used to toggle views of the [Webcast layout](doc:webcast-layout-controls#webcast-host-controls) along with the **Broadcast** and **Record** controls.  All layout views are "on" by default when the event is started.

When you start a webcast you are not automatically broadcasting slides and videos associated with it to your audience. Rev allows you to first start the event so you can preview it before broadcasting it to your audience. 

> 👍 Tip
>
> You must have the Event Admin or Event Host role to start an event.

Functionality that is enabled aside from slides and video (such as chat, Q\&A, and polls) is available to moderators and attendees once you start the event and *before* you begin broadcasting. 

Features that are available once an event is started versus broadcasting:

| Event Started - Features Available                                            | Event Broadcasting - Features Available  |
| :---------------------------------------------------------------------------- | :--------------------------------------- |
| Chat                                                                          | Chat                                     |
| Q\&A                                                                          | Q\&A                                     |
| Polls                                                                         | Polls                                    |
| Invitation text (Moderators only)                                             | Invitation text (Moderators only)        |
| Attendee list (Moderators only)                                               | Attendee list (Moderators only)          |
| Video feed (Moderators only / Attendees displayed "Not broadcasting" message) | Video feed (everyone)                    |
| Presentation slides (Moderators only)                                         | Presentation slides (everyone)           |
| Slide controls (Moderators, if assigned)                                      | Slide controls (Moderators, if assigned) |

> 🚧 Important!
>
> Event Admins are granted **full** access to all of the above while Event Hosts **only** to those events they create or are assigned to.

## Activities During the Webcast

During the webcast, the Event Admin and Hosts have a number of duties.  Assuming that they have started and broadcasted the webcast, they would monitor the webcast for issues.  Issues could include everything from incorrect Webcast settings, inability for attendees to view the webcast, and video source issues.

Once **Broadcasted**, all video sources (except **Producer** and **Webcam and Screenshare**) are displayed to the Event Admin and Host as the attendees will see them.  Because of the streaming and packaging, the video source is delayed.  Event Admins and Hosts should consider the playing video as a confidence monitor.  

In the event of misconfiguration or technical issues, the Event Admin and/or Host have the ability to:

1. In realtime **Edit Webcast** settings.  Not all webcast settings can be edited once the Webcast has started, but please view the  [Edit a Webcast's Settings After it Starts](doc:troubleshooting-a-webcast#edit-a-webcasts-settings-after-it-starts) topic for additional details.
2. **Stop and Restart the event**.  Stopping the event will do a number of things. Most importantly it notifies attendees that the event has completed, which may not be desirable (albeit necessary) during an event.  The restart moves attendees back into the event and reconnects the source (and waits for a Broadcast from the Event Host.).
3. [Restart a Webcast's Video Source](doc:troubleshooting-a-webcast#restart-a-webcasts-video-source).  In this case, attendees are provided a "Please hold on" style message of your choice while the system reconnects to the video source.  This is not available for all Video Sources.

## Recording the Webcast

To record a webcast, you must be broadcasting it and an Account Admin must configure Rev to record events by setting a [primary DME](doc:set-dme-recording-options) player.

When you record a webcast, both the video input stream and any attached PowerPoint presentations (if uploaded) are recorded. If you stop broadcasting or end the event, the recording is also stopped. You may view and edit your recorded events under the [Media](doc:user-menu-options)  > **My Videos** menu.

> 📘 Note
>
> If recording is started/stopped multiple times during a Presentation Profile sourced webcast, each start/stop combination is treated as a *separate* recorded event. Videos are transcoded to the presets specified in transcoding settings for the recording.

<Image title="setToRecordButton.png" alt={605} align="center" src="https://files.readme.io/95c77a2-setToRecordButton.png">
  When recording or "set to record", the button turns red
</Image>

The **Record** button turns red and the text displays **Recording** when clicked.

If the event is paused or not yet broadcasting, the **Record** button may be clicked ahead of time and the webcast is then **set to record** so that it begins recording immediately once broadcasting.

An error message is displayed and you should contact your Account Admin if:

* DMEs are down and Rev is unable to connect and record your event.
* DMEs have reached their storage capacity and have run out of storage space.
* DMEs have reached their maximum simultaneous recordings allowed.

> 👍 Tip
>
> **Record** button visibility and behavior is dictated by the [Webcast Recording Settings](doc:webcast-recording-settings) that are specified by the Account Admin.

## Viewing and Removing Attendees

There may be times when you need to remove a disruptive attendee from a webcast to ensure a positive experience for the remaining attendees. Only **Event Admins/Hosts** and **Event Moderators** (if [enabled](doc:allow-webcast-features#allow-moderators-to-remove-attendees)) may remove an attendee from an event.

<Image title="viewingAttendees.png" alt={720} align="center" src="https://files.readme.io/25b2e9a-viewingAttendees.png">
  The Attendees icon provides insight to all attendees in the webcast, including the ability to remove them if necessary
</Image>

1. Click the **Attendees** icon to display all current attendees viewing the webcast.

2. Click the **Remove** button next to the attendee you want to remove from the event. Note this now toggles to a **Restore** button in the event you want to restore access to the webcast to the removed attendee.

3. You will be prompted to confirm that you want to remove the attendee. Click **Ok**. The attendee is immediately removed and displayed a message that they have been removed.

<Image title="attendeeRemoved.png" alt={805} align="center" src="https://files.readme.io/e8ebd90-attendeeRemoved.png">
  Attendees that are removed are informed that they have been removed
</Image>

> 🚧 Important!
>
> If the removed attendee is an *internal* user, the user is not able to re-access the event unless they are restored by the Event Host or Event Moderator. 
>
> If the removed attendee is a *guest* user, the user is not able to re-access the event if using the same computer and browser or with the same email address.

## Controlling the Webcast

### Host Layout Controls

**Host** layout controls are similar to the [attendee layout controls](doc:webcast-layout-controls) along with the addition of the ability to control the presentation slides.

<Image title="hostControls.png" alt={319} align="center" src="https://files.readme.io/f0caa59-hostControls.png">
  Host controls are similar to the attendee controls with the added ability to control and view slides
</Image>

Use the **Record**, **End Event**, and **Broadcast** buttons to control the event and broadcast it to attendees when ready. The **Record** button does *not* work if you do not have a [recording device](doc:set-dme-recording-options) set up or if the event is not also broadcasting. However, it may be “set to record” by clicking it *before* you begin broadcasting so that when the broadcast is clicked, the recording begins immediately.

<Image title="broadcastControls.png" alt={244} align="center" src="https://files.readme.io/eae039d-broadcastControls.png">
  Broadcasting the event begins streaming it to attendees
</Image>

### Presentation Slide Controls

PowerPoints are controlled by **Event Hosts** (or by **Event Moderators** if specified during set up). Once broadcasting begins, slides are controlled in either the Presentation window or in the Slide carousel depending on preference.

<Image title="slideControl.png" alt={805} align="center" src="https://files.readme.io/91529d2-slideControl.png">
  Slides are controlled by next and back arrows and can also be replaced or deleted by Hosts and/or Moderators (if specified during setup)
</Image>

> 🚧 Important!
>
> If an **Event Moderator** has slide control (during event set up), **Event Admins/Hosts** do *not* see the Slides carousel during the webcast nor are able to navigate and page through the slides. 
>
> However, if an Event Moderator is *not* given slide control during set up, then all Event Admins and or Event Hosts assigned to the webcast have control.
