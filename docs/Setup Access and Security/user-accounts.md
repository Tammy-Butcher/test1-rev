You must have the **Account Admin** role to add or edit a user in Rev. Users are also imported and managed with LDAP groups. Finally, you may also add users (and groups) through a CSV upload process.

> 👍 Tip
>
> A new user is considered an **Unlicensed** account and must be **activated** or **confirmed** so that the account status becomes **Active**.

Once the user is **Active**, you may assign the user a **Role** that has certain permissions defined such as the ability to view, edit, and upload content. You may also add the user to a **Group**. 

To access the Users module:

1. Navigate to **Users** > **Users** menu in the [Admin Menu Options](doc:admin-menu-options). 

<Image alt="The Users Menu is accessible to Account Admins under the Users Header Navigation Menu" align="center" src="https://files.readme.io/6b697d4-usersMenuDropdown.png">
  The Users Menu is accessible to Account Admins under the Users Header Navigation Menu
</Image>

2. The **Users** module is displayed. Use it to add, edit, upload, and manage the user accounts in your portal.

## Add or Edit a User

Most users are imported and managed with LDAP groups in Rev. You may also add and edit users or groups through **Users** module.

To add a new user, click the **Add User** button on the **Users** module.  You may edit a user by clicking the Username.

> 📘 Note
>
> If you have imported your users from an [LDAP group](doc:groups#import-an-ldap-group), you are only able to edit the **Preferred Language**, **Assigned Role**, and **Rev Assigned Group** of the accounts. All other attributes must be edited from LDAP and the Users module may not be used in this case.

Complete the fields described below and click **Create User** to save the new user.

| Field                | Description                                                                                                                                                       |
| :------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First Name           | First name of the account holder. Text only.                                                                                                                      |
| Last Name (Required) | Last name of the account holder. Text only.                                                                                                                       |
| Contact Email        | Email of the account holder. Must be a valid email address.                                                                                                       |
| Title                | Preferred title of the account holder. Text and numerical input accepted.                                                                                         |
| Phone Number         | Phone number of the account holder.                                                                                                                               |
| Preferred Language   | Preferred language of the account holder.                                                                                                                         |
| Username (Required)  | Used to log in to Rev. Email address is also accepted. Field *must* be unique in Rev. This is *not* case sensitive. This field name may not be edited once saved. |

You do not have to add groups or roles when you initially create a User (a default role of **Media Viewer** is assigned).

As soon as you click the **Create User** button, the user account is set to **Unlicensed** status.  An email is generated by Rev and sent to the user so that they may create their own password and security question.  The account is set to **Active** status once the user logs-in for the first time.

> 🚧 Important!
>
> If you do not have an email server set up, you have to manually confirm and activate each user that is created. This is not recommended. You should also keep in mind that if your Rev portal is not ready for launch, you should delay setting up user accounts.
>
> If a user is created on a portal with [SSO](doc:configure-single-sign-on-sso#sso-with-user-provisioning) enabled, the account is created with no user confirmation required and no email is generated. However, account status remains **Unlicensed** until the user logs-in for the first time and becomes **Active**.
>
> If users are managed by LDAP, these options are not available. Instead, users are imported with groups and LDAP.

## Assign a Role or Group to a User

Use the **Role Assignment** and **Group Assignment** sections to assign (or remove) roles and groups to a user as needed.

There are several [pre-defined roles](doc:roles-and-permissions) that may be added to a user account.  The **Media Viewer** role is assigned by default. At least one role must be assigned or you will not be able to save the user account.

Moving a role from the **Assigned Roles** column back to the **Available Roles** column removes that role (and all associated permissions) from the user.

<Image title="assignRoleToUser.png" alt={1075} align="center" src="https://files.readme.io/e8e3897-assignRoleToUser.png">
  The Media Viewer role is assigned by default
</Image>

To add the user to a **Group**, type the group name in the **Find Items** box. Click the name and then **Done** to add the group to the **Group Assignment**.  This adds the user to the **Group** upon saving.

To remove a user from a group, click the **X** next to the group name.

<Image title="assignGroupToUser.png" alt={947} align="center" src="https://files.readme.io/b9411b8-assignGroupToUser.png">
  Any groups typed in the Find Items box appear automatically so that you may add the User to the group
</Image>

> 📘 Note
>
> It is not a requirement that a group is assigned when creating or editing a User. You may also add a user account to several groups at once using the upload functionality.

## Upload Users and Groups via CSV File

You may quickly upload and edit multiple **Users** and **Groups** at once using a .csv file if you need to do so without an LDAP import.  If the groups you associate in the .csv do not already exist, they are created during the process.

> ❗️ Warning!
>
> You *must* save the file encoded in the **UTF-8** format. Otherwise certain characters may not be displayed correctly.
>
> There is a limitation of 300k rows allowed.

* Only .csv files are accepted
* Field names must be in the first row of the file (see sample below)
* Certain fields must be unique and are also required (noted below)
* Users are **Unlicensed** and do not count toward your licenses until logged in
* Users are assigned to the **Media Viewer** role only

For each row:

* If a user row is missing a required field, the user account is not created.
* If a user account with the same email address already exists in Rev, the new user account is not created.
* If a user account with the same username already exists in Rev, the new user account is not created.

### Upload the User Account CSV File

Once the CSV file is formatted correctly, click the **Upload Users** button to begin the upload process.

> 🚧 Important!
>
> As noted, there is a limitation of 300k rows allowed.

<Image title="uploadUsers.png" alt={446} align="center" src="https://files.readme.io/77ab67f-uploadUsers.png">
  Use the Upload Users button to upload your CSV file once you are confident it is formatted correctly
</Image>

* Click the **Create Groups** checkbox if you are creating new groups.
* If your Users should be added to the Groups in the GroupNames column (in addition to existing groups they already belong to), select **Append**. This means you are *editing* Users.
* Select **Replace** to add Users to the Groups specified in GroupNames column and remove them from all other groups they previously belonged to. This means that *only* those groups in the .csv file are associated to the user account going forward.
* Click the **Submit** button when you are ready to upload your file. Users receive an email notification to log in and verify their accounts through the usual process unless you are using SSO.
* You receive a notification in Rev and through email once your upload is complete stating how many Users and Groups are created or if there were any errors.

> 📘 Note
>
> [Child accounts](doc:view-and-edit-account-details#add-a-child-account) are not permitted to modify account Users by using the upload .csv feature from the Parent account.
>
> If there is a need to modify Users in a child account via the .csv upload method, then those changes should be made directly in that child account.

> 👍 Tip
>
> The **Submit** button does not become available until you have attached a CSV file.
>
> If you plan on adding or editing several accounts, the upload feature allows a test on one row. A test upload is recommended *before* creating several groups or deleting/suspending several accounts to make sure your settings and .csv file accomplish what you intend.

## Download a List of All Users in Rev

Use the **Download** button to export a CSV file of all Users in the system. For those portals that have large amounts of Users, the download process prepares in the background. A notification and email are sent to the Admin Account that prompts the download when it is ready.

<Image title="downloadPrep.png" alt={534} align="center" src="https://files.readme.io/0b26a3d-downloadPrep.png">
  If necessary, the download is prepared in the background and you are notified when it is ready
</Image>

The following fields are contained in the download:

* Username
* First Name
* Last Name
* Email Address
* Title
* Phone Number
* Status
  * Active
  * Unlicensed
  * Awaiting Password Reset
  * Awaiting Security Question Reset
* Licensed
  * True or False
* Preferred Language
* Roles
* Group Assignments
* LDAP Group Assignment
* Channel Names
* Source
  * System
  * LDAP

## View License Usage Summary for a Rev Portal

The **Users Module** displays at a glance how many total Users are in your portal and how many licenses you have consumed versus how many remain unused.

<Image title="licensingStatus.png" alt={911} align="center" src="https://files.readme.io/379444a-licensingStatus.png">
  The Users Module always displays licensing usage stats for your portal
</Image>

Keep in mind:

* Users are *not* counted as [Licensed](doc:rev-license-types-and-add-ons) users until they log in and verify their account.
* **Unlicensed** and **Suspended** status states do *not* count toward the number of Licensed users displayed.
* **Active**, **Locked Out**, **Awaiting Password Reset**, and **Awaiting Security Question Reset** *do* count toward the number of **Licensed** users for a Rev portal.
* If a user attempts to log in to a Rev portal that does *not* have any licenses available, the user will not be able to log in and a message is displayed to contact the Rev Account Administrator.

## Reset a User's Password

There may be times when you need to manually reset a User's password. Note that if Users are managed through LDAP, passwords and security options are not editable or managed through the Rev portal.

To reset a User's password in Rev:

1. Navigate to the User's profile under the [User module](doc:user-accounts).

2. Under the **Administrative Actions** section click the **Reset Password** button. This button is only available if the account status is **Active** and is not **Locked Out**.

3. A reset password email is then sent to the User with a link to reset their password.

4. The User's status is then set to **Awaiting Password Reset**.

<Image title="awaitingPasswordResetStatus.png" alt={296} align="center" src="https://files.readme.io/ff37376-awaitingPasswordResetStatus.png">
  User account status changes to Awaiting Password Reset after the Password Reset button is clicked that prompts an email to be sent to the User
</Image>

5. The User must answer their security question to reset their password. Password complexity rules set for the system still apply.

6. The password reset link remains in effect for 72 hours.

7. To manually send the password URL, click the **Show** button (similar to obtaining the confirmation URL manually).

> 👍 Tip
>
> The button functions available in **Administrative Actions** vary based on the User's account status. 
>
> A few use case(s) include: 
>
> * **Unlicensed** status and you are able to obtain the **User Confirmation URL** to complete the registration process.
>
> * **Locked Out** status and you are able to **Unlock** the account.

## Unlock a User's Account

If a user is locked out of his/her user account and is unable to reset the password through the **Forgot Password** link, Account Admins may either unlock the account or reset the password as the case may be. The exception to this is if Users are managed by LDAP. LDAP users are not managed through the Rev interface and passwords / security options must be managed through LDAP instead.

To unlock a User that is locked out:

1. Navigate to the User's account under the [User module](doc:user-accounts).

2. Under **Administrative Actions** > click the **Reset Password** button to generate an entirely new password for the User.  **View**: [Reset a User’s Password](doc:user-accounts#reset-a-users-password).

3. Click **Unlock** to unlock the User's account. The previous password will still be in place.

4. The User's account status must be either **Active** or in **Locked Out** status for these two buttons to be present at the same time.

<Image title="unlockUserAccount.png" alt={596} align="center" src="https://files.readme.io/77c910f-unlockUserAccount.png">
  If the User's account is Active or Locked Out you may reset the password or unlock the account
</Image>

## Reset a Security Question

If a User is locked out and also incorrectly answers the security question when attempting to reset their password through the **Forgot Password** link, Account Admins may reset the question for the account.

<Image title="maxSecurityQuestionAttempts.png" alt={693} align="center" src="https://files.readme.io/81ba47c-maxSecurityQuestionAttempts.png">
  This User has surpassed the number of attempts configured and needs Account Admin assistance
</Image>

To reset a User's security question:

1. Navigate to the User's account under the [User module](doc:user-accounts).

2. Under **Administrative Actions** > click the **Reset Security Question** button to generate an email to the user that prompts the creation of a new password and security question.

3. This button is only available if the User has incorrectly answered their security question when clicking the (**Forgot Password?**) hyperlink on the login screen. The amount of times they must answer incorrectly is set under **Security Settings**.

<Image title="resetSecurityQuestionButton.png" alt={638} align="center" src="https://files.readme.io/c6acd7e-resetSecurityQuestionButton.png">
  This button appears if the User incorrectly answers their Security Question the number of times configured when attempting to reset their Password
</Image>

4. The reset link stays in effect for 72 hours.

5. If you need to manually send the reset URL, you may do so from the User's **Administrative Actions** section by clicking the **Show** button.

## Suspend a User

Suspended Users may not log in and, if the User is logged in at the time the account is suspended, they are logged out immediately. If a User attempts to log in after the account is suspended, an error message informs them that their account is suspended and to contact an Account Admin.

* You may not suspend your own account.
* Consider suspending accounts as opposed to deleting them.
* Suspended accounts are noted in the **Status** column of the Users module.
* An LDAP User may be suspended if the source of the account is removed (the LDAP group). View: **Delete or Suspend an LDAP Group or User**
* Users that are suspended manually through this drop-down are not deleted when an LDAP sync is run again if the **Delete Suspended Users** checkbox is enabled. (View: **LDAP Server Synchronization Settings** for details on how to delete users that have never logged in to Rev and are suspended.)

<Image title="suspendedUserStatus.png" alt={221} align="center" src="https://files.readme.io/c7e2d23-suspendedUserStatus.png">
  The Status column in the Users module denotes the Suspended status
</Image>

To suspend a User:

1. Navigate to the User's account under the [User module](doc:user-accounts).

2. In the **Actions** dropdown, click the **Suspend User** link. This is a toggle and switches to **Activate User** if/when you need to reactivate the User.

<Image title="suspendUserLink.png" alt={274} align="center" src="https://files.readme.io/7c1d42d-suspendUserLink.png">
  Clicking Suspend User suspends the User account and then switches to Activate User in the event you need to reactivate the account
</Image>

## Delete a User

> ❗️ Warning!
>
> Users that are deleted may not be recovered so use this feature with extreme caution!

* You may not delete your own account.
* Consider suspending accounts as opposed to deleting them.
* You may delete Users imported through LDAP, however, if a sync occurs again, they are re-imported. It is better to manage the deletions through LDAP. Only suspended users that have never logged in are automatically deleted forever when synced. (View: **LDAP Server Synchronization Settings** for details on how to delete users that have never logged in to Rev and are suspended.)
* Users that are suspended manually through this drop-down are not deleted when an LDAP sync is run again if the **Delete Suspended Users** checkbox is enabled. (View: **LDAP Server Synchronization Settings** for details on how to delete users that have never logged in to Rev and are suspended.)

<Image title="deleteUserLink.png" alt={233} align="center" src="https://files.readme.io/e61aa54-deleteUserLink.png">
  Click the Delete link on Actions dropdown to delete a User.  This process may not be reversed!
</Image>

## Lost or Blocked User Registration Emails

When a new User is created, the account status is automatically set to **Unlicensed**. An email notification is generated with instructions for setting up a password and security question if an email server has been set up.

The new User needs to complete their registration by logging in to the Rev portal. The status of the account is then modified to **Active**.

There may be times when the User is unable to complete this email verification (the email is blocked by a spam filter or the email server is not set up when the email is sent, for example). Account Admins are able to obtain the URL and manually send an email in this case.

To obtain a User's confirmation URL:

1. Navigate to the User's account under the [User module](doc:user-accounts).

2. Under **Administrative Actions** > click the **Show** link. This button is only available if the User's status is **Unlicensed**.

<Image title="getUserUrl.png" alt={556} align="center" src="https://files.readme.io/8ec824e-getUserUrl.png">
  Click the Show button link to obtain the confirmation URL to manually send the user the login URL needed for registration completion
</Image>

3. The **User Confirmation URL** appears.

4. You may send this URL to the user in a new email to complete the registration and activation process.

## Create a User API Key

Once the new User account is created and saved, you are able to generate a **User-level API key** and secret for authentication and authorization for use with Rev's [User Login API](ref:authenticateuser). When this key is used, the system respects the role/permission of the user that the key belongs to when responding to the API calls.   

A Rev license count is consumed when this key is used *only* if the User account is *both* in **Unlicensed** and **Active** status.  Also, if the User is suspended, the key does not work.

> 🚧 Important!
>
> The user-level API key created here is different than Rev's [system-level API keys](doc:create-an-api-key) that are used by Vbrick devices (DME, Encoders, AppleTV, and so forth).

To generate a User API key:

1. Navigate to the User account and edit the account.

2. Scroll to the **API Key** section and click the **Generate API Key** button.

<Image title="generateKey.png" alt={402} align="center" src="https://files.readme.io/bc713a2-generateKey.png">
  Click the Generate API Key button to create an API Key and Secret for a User Account
</Image>

3. Be aware that the first time the API Key is generated is also the *only* time the Secret is visible.

<Image title="keyGenerated.png" alt={502} align="center" src="https://files.readme.io/8c3ab8e-keyGenerated.png">
  The Secret can be viewed and copied only after the first time it is generated.  It must be regenerated if you need to view it again later.
</Image>

4. You can copy the API Key, delete it, or regenerate it.  You may *not* view the Secret again once you have saved the User.  You must regenerate the API Key to retrieve the Secret again.

<Image title="keyFinalized.png" alt={502} align="center" src="https://files.readme.io/a1ec3e2-keyFinalized.png">
  Click the Copy button next to the API Key to copy it
</Image>
