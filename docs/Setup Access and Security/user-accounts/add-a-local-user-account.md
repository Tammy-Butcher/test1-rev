Rev supports importing and managing user accounts through [LDAP groups](doc:groups#ldap-groups)  and [Okta SCIM](doc:enable-okta-scim). You may also add and edit users or groups locally through **Users **module.

To add a new user, click the **Add User** button on the **Users **module.  You may edit a previously added user by clicking the Username.

> 📘 Note
> 
> If you have imported your users from an [LDAP group](doc:groups#import-an-ldap-group) or [Okta SCIM](doc:enable-okta-scim), you are only able to edit the **Preferred Language**, **Assigned Role**, and **Rev Assigned Group** of the accounts. All other attributes must be edited from LDAP and Okta respectively and the Users module may not be used in this case.

Complete the fields described below and click **Create User** to save the new user.

| Field                | Description                                                                                                                                                       |
| :------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First Name           | First name of the account holder. Text only.                                                                                                                      |
| Last Name (Required) | Last name of the account holder. Text only.                                                                                                                       |
| Contact Email        | Email of the account holder. Must be a valid email address.                                                                                                       |
| Title                | Preferred title of the account holder. Text and numerical input accepted.                                                                                         |
| Phone Number         | Phone number of the account holder.                                                                                                                               |
| Preferred Language   | Preferred language of the account holder.                                                                                                                         |
| Username (Required)  | Used to log in to Rev. Email address is also accepted. Field _must_ be unique in Rev. This is _not_ case sensitive. This field name may not be edited once saved. |

You do not have to add groups or roles when you initially create a user (a default role of **Media Viewer** is assigned).

## User Access Management

As soon as you click the **Create User** button, the user account is set to **Unlicensed **status.  This **User State** is reflected in the **Access Management** section of the user account form. This section also contains the state of the user's password and, if a password expiration rule has been configured, how much time will elapse before it expires.

An email is generated by Rev and sent to the user so that they may create their own password and security question.  The account is set to **Active **status once the user logs-in for the first time.

> 🚧 Important!
> 
> If you do not have an email server set up, you have to manually confirm and activate each user that is created. This is not recommended. You should also keep in mind that if your Rev portal is not ready for launch, you should delay setting up user accounts.
> 
> If a user is created on a portal with [SSO](doc:configure-single-sign-on-sso#sso-with-user-provisioning) enabled, the account is created with no user confirmation required and no email is generated. However, account status remains **Unlicensed **until the user logs-in for the first time and becomes **Active**.
> 
> If users are managed by LDAP or Okta, these options are not available. Instead, users are imported with groups and LDAP/Okta.

## Lost or Blocked User Registration Emails

As noted above, when a new user account is created, the account status is automatically set to **Unlicensed**. An email notification is generated with instructions for setting up a password and security question if an email server has been set up.

The new user needs to complete their registration by logging in to the Rev portal. The status of the account is then updated to **Active**.

There may be times when the user is unable to complete this email verification (the email is blocked by a spam filter or the email server is not set up when the email is sent, for example). Account Admins are able to obtain the URL and manually send an email in this case.

To obtain a User's confirmation URL:

1. Navigate to the User's account under the [User module](doc:user-accounts).

2. Under **Access Management** > click the **Show **button next to **User Confirmation URL**. This button is only available if the user account status is **Unlicensed**.
